# 보안

## 커밋 전 체크리스트
- [ ] 코드에 하드코딩된 비밀, API 키, 비밀번호, 토큰이 없는가?
- [ ] 모든 사용자 입력을 검증하고 sanitize했는가?
- [ ] SQL 쿼리가 parameterized 문을 사용하는가 (절대 문자열 연결 금지).
- [ ] API 엔드포인트에 적절한 인증/인가 체크가 있는가?
- [ ] 민감한 데이터가 로깅되지 않았는가 (비밀번호, 토큰, PII, 카드 번호).
- [ ] 에러 응답이 내부 상세 정보를 노출하지 않는가 (스택 트레이스, DB 스키마, 파일 경로).

## 인증 & 인가
- JWT 또는 세션 기반 인증 사용. 암호화를 직접 구현하지 말 것.
- 미들웨어/필터로 매 요청마다 토큰 검증.
- 역할 기반 접근 제어(RBAC) 구현. 서비스 레이어에서 권한 확인.
- bcrypt 또는 argon2로 비밀번호 해싱. MD5나 SHA 금지.
- 토큰 만료: 단기 액세스 토큰(15-60분), 장기 리프레시 토큰.

## 비밀 관리
- 환경 변수 또는 비밀 관리자(Vault, AWS Secrets Manager, K8s Secrets)에 저장.
- 애플리케이션 시작 시 필수 비밀 모두 검증. 없으면 즉시 실패.
- `.env` 파일 커밋 금지. 즉시 `.gitignore`에 추가.
- 노출된 비밀은 즉시 회전. 커밋된 모든 비밀을 손상된 것으로 간주.

## API 보안
- CORS는 명시적 출처로 활성화. 프로덕션에서 `*` 금지.
- 모든 공개 엔드포인트에 rate limiting. 인증 엔드포인트는 더 엄격하게.
- 모든 곳에서 HTTPS 사용. HTTP는 HTTPS로 리다이렉트.
- Content-Type 헤더 검증. 예상 외 타입 거부.
- 보안 헤더 설정: `X-Content-Type-Options`, `X-Frame-Options`, `Strict-Transport-Security`.

## 데이터 보호
- 저장된 민감 데이터 암호화 (DB 레벨 또는 필드 레벨).
- 전송 중 모든 데이터에 TLS 사용 (DB 연결, API 호출, 메시지 큐).
- 민감한 작업 감사 로깅 구현 (로그인, 데이터 접근, 관리자 작업).
- DB 사용자, API 키, 서비스 계정에 최소 권한 원칙 적용.

## 컨테이너 & 인프라 보안
- Docker 이미지 취약점 스캔 (Trivy, Snyk).
- non-root로 컨테이너 실행. 불필요한 Linux 기능 제거.
- K8s 네트워크 정책으로 pod-to-pod 통신 제한.
- 의존성 최신 상태 유지. Dependabot 등으로 CVE 모니터링.
